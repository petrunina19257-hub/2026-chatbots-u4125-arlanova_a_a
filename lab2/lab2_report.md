## 1. Описание интеграции

### Рабочая версия (Apps Script): Telegram API + Google Таблица

Бот на Apps Script соединяет два внешних источника данных:

| Источник | Тип из задания | Как подключён | Что даёт |
|---|---|---|---|
| **Telegram Bot API** | публичный API | `UrlFetchApp.fetch` → метод `getUpdates` | новые сообщения из лички и общего чата |
| **Google Таблица** | работа с данными | встроенный сервис `SpreadsheetApp` | хранилище задач и одновременно интерфейс: задачи видно, их можно фильтровать и закрывать |

Структура листа с задачами:

| Дата | Чат | Автор | Username | Задача | Статус |
|---|---|---|---|---|---|
| дата и время записи | название группы или имя в личке | имя и фамилия из Telegram | `@username` | текст после `/task` | `new` → `закрыто` (вручную) |

Почему именно так: таблица уже есть у каждого, кто работает в Google, её не нужно разворачивать. Коллегам можно дать доступ к ней, а фильтр по колонке «Статус» сразу показывает, что ещё не сделано. Никаких ключей, кроме токена Telegram, не нужно: скрипт пишет в таблицу от имени её владельца.

### Расширенная версия (Python): какие источники данных выбраны

Бот-ассистент на Python подключён сразу к трём источникам:

| Источник | Тип из задания | Что даёт |
|---|---|---|
| **Google Таблица** через Google Sheets API | публичный API | каждая задача автоматически появляется строкой в таблице и обновляется, когда меняются статус или приоритет |
| **Excel / CSV файлы** | работа с файлами | `/export` присылает `.xlsx` со всеми задачами; присланный боту `.xlsx`/`.csv` импортируется как список задач |
| **SQLite** | база данных | поверх базы из лабы 1 появились поиск, выборка за неделю, статистика |

### Почему именно эти

- **Google Таблица** — её удобно открыть с компьютера, отфильтровать и показать другим, а бот остаётся быстрым способом добавить задачу с телефона. Задачи пишутся на лист `TaskHunter`.
- **Excel** — задачи часто уже лежат в файлах (план от руководителя, список дел из другого сервиса). Импорт загружает их в бота за одно действие, а экспорт помогает сделать отчёт.
- **SQLite** остаётся главным хранилищем: бот работает, даже если Google недоступен, а таблица служит «зеркалом» базы.

## 3. Реализация

### Как работает интеграция в версии на Apps Script

```
Telegram ◄── getUpdates (UrlFetchApp) ── pollTelegram()  ← триггер по времени, раз в минуту
                                            │
                                            ├── PropertiesService: last_update_id (чтобы не задваивать)
                                            │
                                            └── writeTask() ──► SpreadsheetApp ──► первый лист таблицы
```

Ключевой фрагмент — запись задачи в таблицу:

```javascript
function writeTask(message, taskText) {
  const user = message.from || {};
  const sheet = SpreadsheetApp.openById(SPREADSHEET_ID).getSheets()[0];

  sheet.appendRow([
    new Date(),
    message.chat.title || message.chat.first_name || '',   // группа или имя в личке
    [user.first_name, user.last_name].filter(Boolean).join(' '),
    user.username ? '@' + user.username : '',
    taskText,
    'new'
  ]);
}
```

### Как работает интеграция в версии на Python

```
Telegram ──► bot.py ──► SQLite (tasks.db)          — главное хранилище
                │
                ├──► sheets.py ──► Google Sheets API — зеркало: upsert строки по id
                │                  (asyncio.to_thread, ошибки → лог)
                │
                └──► excel_io.py ◄─► .xlsx / .csv  — /export и импорт файлов
```

1. При запуске `SheetSync.from_env()` подключается к таблице. Если нет настроек, файла ключа или доступа — возвращает `None`, и бот работает без таблицы.
2. После каждого изменения задачи бот вызывает `sync_task()`: читает задачу из базы и обновляет её строку в таблице или добавляет новую. Если задачу удалили — строка удаляется.
3. `/export` собирает Excel-файл в памяти и отправляет его документом.
4. На присланный документ бот скачивает файл, `read_import_file()` находит колонки по названиям, каждая строка проходит через тот же разбор, что и обычное сообщение, и сохраняется в базу.

### Ключевые фрагменты кода

Синхронизация с таблицей, которая не блокирует бота и не роняет его при ошибке (`bot.py`):

```python
async def sync_task(context, chat, task_id: int) -> None:
    sync = sheet(context)
    if sync is None:
        return
    row = storage(context).get_task(chat.id, task_id)
    try:
        if row is None:
            await asyncio.to_thread(sync.delete, task_id)
        else:
            await asyncio.to_thread(sync.upsert, task_values(row, chat_title(chat), TZ))
    except Exception:
        logger.exception("Google Sheets sync failed for task #%s", task_id)
```

Upsert строки по id (`sheets.py`):

```python
def upsert(self, values):
    row_number = self._find_row(int(values[0]))
    if row_number is None:
        self.worksheet.append_row(values, value_input_option="RAW")
    else:
        self.worksheet.update(range_name=f"A{row_number}", values=[values], raw=True)
```

Чтение CSV из русского Excel (`excel_io.py`):

```python
for encoding in ("utf-8-sig", "cp1251"):
```

Статистика одним SQL-запросом (`database.py`):

```sql
SELECT COUNT(*) AS total,
       SUM(status = 'open') AS open,
       SUM(status = 'done') AS done,
       SUM(status = 'open' AND due_at IS NOT NULL AND due_at < :now) AS overdue,
```

## 5. Трудности и решения

| Проблема | Решение |
|---|---|
| Apps Script: в группе команда приходит как `/task@task_hunter_bot` | Регулярное выражение учитывает необязательное `@имя_бота` |
| Apps Script: задачи не должны записываться в таблицу дважды | `offset` = последний `update_id` + 1, номер хранится в `PropertiesService` |
| Apps Script: закрывать задачи из Telegram нельзя | Статус меняется вручную в таблице; в версии на Python для этого есть `/done` и кнопка «✅ Готово» |
| У новых сервисных аккаунтов нет квоты на Google Drive, поэтому создание таблицы от их имени может завершиться ошибкой | Таблица создаётся вручную в своём аккаунте и открывается сервисному аккаунту с правом «Редактор» |
| gspread синхронный: пока идёт запрос к Google, бот не отвечает другим пользователям | Вызовы через `asyncio.to_thread` |
| Если Google упал, бот не должен падать вместе с ним | Подключение и каждая синхронизация обёрнуты в `try/except`, ошибка пишется в лог, главное хранилище — SQLite |
| `LIKE` в SQLite сравнивает без учёта регистра только латиницу | Фильтрация в Python через `casefold()` |
| Excel хранит дату как datetime, а 00:00 — это «без времени» | Ячейка-дата превращается в строку `дд.мм.гггг` или `дд.мм.гггг чч:мм` и проходит через тот же парсер дедлайнов |
| CSV из русского Excel в кодировке cp1251 и с `;` | Перебор кодировок + `csv.Sniffer` для разделителя |
| В базе из лабы 1 нет новой колонки | Миграция при старте через `PRAGMA table_info` + `ALTER TABLE` |

## 6. Выводы

**Что получилось хорошо.** Версия на Apps Script связывает Telegram и Google Таблицу без сервера и без отдельных ключей, и ей реально пользуются: 9 задач, 7 из них закрыты. Версия на Python работает сразу с тремя источниками данных, но ни один из них не может его «уронить»: Google необязателен, все ошибки файлов понятны пользователю. Импорт использует тот же разбор, что и обычные сообщения, поэтому в Excel можно писать «завтра» или «до пятницы». Фейковый Google-лист позволил протестировать синхронизацию без интернета и ключей.

**Что можно улучшить.** Двусторонняя синхронизация (изменил статус в таблице — изменилось в боте); отдельный лист для каждого чата; импорт из Google Таблицы по ссылке; экспорт только открытых или только за период.

**Чему научились.** Писать промпт с описанием того, **что должно происходить при сбое** внешнего сервиса, а не только при успехе. Просить LLM сразу писать тесты с фейковыми внешними сервисами — так интеграцию можно проверить до получения ключей.
