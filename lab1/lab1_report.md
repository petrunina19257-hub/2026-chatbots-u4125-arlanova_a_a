# Лабораторная работа 1. Создание первого Telegram-бота без программирования

**Бот:** [@task_hunter_bot](https://t.me/task_hunter_bot) · **Код:** [`lab1/bot`](bot/)

## 1. Описание задачи

Выбран вариант 3 — **бот-ассистент для задач**.

### Какую проблему решает бот

Задачи приходят со всех сторон: в чатах, на парах, в голове по дороге. Записывать их в приложение-планировщик долго: открыть, выбрать дату, выбрать приоритет. Поэтому задачи теряются или записываются куда попало.

Бот убирает лишние шаги: задача отправляется **одним сообщением обычным текстом**, как заметка себе в «Избранное». Всё остальное бот делает сам:

- понимает приоритет по словам: «срочно», «важно», `!!` → 🔴, «не срочно» → 🟢;
- понимает дедлайн: «завтра в 15:00», «до пятницы», «через 2 часа», «20.10», «5 ноября»;
- убирает распознанное из текста: «Срочно отправить отчёт завтра в 15:00» → «Отправить отчёт», 🔴, завтра 15:00;
- сортирует список дел: сначала срочное, потом по ближайшему дедлайну;
- напоминает за час до дедлайна, под напоминанием кнопки «✅ Готово» и «⏰ +1 час»;
- каждое утро в 09:00 присылает дайджест: что сделать сегодня и что просрочено.

### Почему выбрана эта задача

Задачи — то, с чем я сталкиваюсь каждый день: учёба, работа, бытовые дела. Готовые планировщики требуют много действий на одну задачу, а Telegram всегда под рукой. Поэтому хотелось сделать ассистента, которым можно пользоваться каждый день, а не учебный пример ради сдачи. Кроме того, этот вариант хорошо развивается в следующих лабах: в лабе 2 к нему подключаются Google Таблица и Excel, в лабе 3 — живые пользователи.

### Исходный промпт

```
Создай Telegram-бота на Python с использованием библиотеки python-telegram-bot.

Функционал бота:
- Бот-ассистент для задач: принимает задачи обычным текстом. В личке любое
  сообщение — это задача, в группе — только /task, упоминание бота или ответ
  на его сообщение.
- Сам определяет приоритет: «срочно», «важно», «!!» — высокий; «не срочно»,
  «#потом» — низкий; иначе средний.
- Сам определяет дедлайн на русском: сегодня, завтра, послезавтра, дни недели
  в любом падеже («до пятницы», «в среду»), 20.10, 20.10.2026, «20 октября»,
  время 18:30, «через N минут/часов/дней/недель». Часовой пояс — Москва.
- Вытаскивает исполнителя (@username).
- Команды: /start, /help, /list (сначала высокий приоритет, потом ближайший
  дедлайн), /today (на сегодня и просроченные), /done N, /del N,
  /prio N высокий|средний|низкий, /digest on|off, /task текст.
- Напоминания: за час до дедлайна (если указано время) или в 10:00 в день
  дедлайна; под напоминанием кнопки «✅ Готово» и «⏰ +1 час».
- Каждое утро в 09:00 — дайджест с задачами на сегодня.

Требования:
- Бот должен быть простым и понятным
- Код должен быть хорошо прокомментирован (комментарии на русском)
- Использовать файл для хранения данных (SQLite)
- Добавить обработку ошибок: неверные аргументы команд, экранирование HTML
  в тексте задач, ошибки отправки сообщений, глобальный error handler
- Разбор текста вынеси в отдельный модуль и покрой автотестами

Создай:
1. Файл bot.py с кодом бота
2. Файл requirements.txt с зависимостями
3. Файл README.md с инструкцией по запуску
4. Файл .env.example для примера конфигурации
```

### Итерации и улучшения

| # | Что заметили | Что попросили у LLM | Результат |
|---|---|---|---|
| 1 | Автотест на сборку приложения упал: ожидали 0 фоновых задач в JobQueue, а их 2 | «Проверь, когда JobQueue регистрирует задачи, и исправь тест» | Задачи регистрируются сразу при `build()` — исправлен тест, сам код был верным |

## 3. Стек технологий

| Библиотека | Зачем | Почему она |
|---|---|---|
| Python 3.9+ | язык | стандарт для Telegram-ботов, есть на macOS из коробки |
| [python-telegram-bot](https://python-telegram-bot.org/) 21.10 `[job-queue]` | работа с Telegram API, команды, inline-кнопки | рекомендована в задании; асинхронная; встроенный **JobQueue** (на APScheduler) — для напоминаний и дайджеста не нужен отдельный планировщик |
| sqlite3 (встроена в Python) | хранение задач | не нужен сервер БД, вся база в одном файле `tasks.db`; в отличие от JSON, можно сортировать и фильтровать прямо SQL-запросом |
| python-dotenv | чтение `.env` | токен не попадает в код и в git |
| zoneinfo (встроена) | часовой пояс | дедлайны считаются по Москве, в базе время хранится в UTC |
| unittest (встроен) | автотесты | 16 тестов на разбор дат, приоритеты, базу и сборку бота — без интернета |

## 5. Трудности и решения

| Проблема | Решение |
|---|---|
| Русские даты пишут по-разному: «до пятницы», «в пятницу», «к пятнице» | Регулярные выражения по основе слова (`пятниц\w*`), «послезавтра» проверяется раньше «завтра», потому что содержит его внутри |
| «До пятницы», написанное в пятницу — это сегодня или через неделю? | Решили, что это следующая пятница: так дедлайн не окажется в прошлом |
| Дата без года, которая уже прошла («до 01.02» в октябре) | Переносим на следующий год |
| Время в базе: сравнивать даты разных часовых поясов строками нельзя | В базе всё хранится в UTC в формате `YYYY-MM-DD HH:MM:SS` — такие строки правильно сравниваются прямо в SQL |
| Пользователь пишет в задаче `<` или `<b>`, а сообщения отправляются в HTML-разметке | Весь пользовательский текст экранируется через `html.escape` |
| Нет реального токена при разработке | Автотесты и офлайн-прогон: в настоящий `Application` подавались поддельные сообщения Telegram, а все запросы к API перехватывались. Так проверены все команды, кнопки и группы ещё до запуска |

## 6. Выводы

**Что получилось хорошо.** Бот понимает задачи, написанные обычным языком, — не нужно запоминать никакой синтаксис. Напоминания с кнопками «Готово» и «+1 час» убирают лишние действия. Разбор текста вынесен в отдельный модуль и покрыт тестами, поэтому LLM могла смело его менять: если что-то ломалось, тест сразу это показывал.

**Что можно улучшить.** Редактирование текста и дедлайна уже созданной задачи; повторяющиеся задачи («каждый понедельник»); выбор времени дайджеста для каждого пользователя; распознавание голосовых сообщений.

**Чему научились.** Хороший промпт описывает не только «что сделать», но и **крайние случаи** («что если дата уже прошла», «что если текст пустой») и **как проверить результат** (автотесты). Лучше всего работает короткий цикл: запустить → посмотреть на реальный ответ бота → попросить исправить конкретную мелочь.
